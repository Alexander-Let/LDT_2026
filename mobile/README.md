# Питомец Финни — мобильное приложение

Игра по финансовой грамотности для детей 7–11 лет. Хакатон ЛЦТ 2026.

Android-приложение на Flutter. **Local-first**: весь игровой цикл работает офлайн
в SQLite, бэкенд — синхронизация поверх (игровое состояние, контент-бандл,
родительские бонусы). Подробный конспект контракта бэкенда — в [docs/BACKEND.md](docs/BACKEND.md).

UI построен по макетам Figma «segee»
(`https://www.figma.com/design/xGhcmLpTAyTC2y7ucB7lvQ/segee`, тёмная тема).
Светлая тема — черновик в `AppColors.light`, доработаем когда появится макет.

## Стек

- Flutter 3.47 / Dart 3.13
- Состояние: `flutter_riverpod` 2.x, **без кодогенерации** (Notifier/AsyncNotifier/FutureProvider)
- HTTP: `dio` (Bearer device_token через interceptor)
- Локальная БД: `sqflite` + `path` (БД `finni.db`)
- Токен устройства: `flutter_secure_storage`
- Модели — руками с `fromJson`/`toJson`, без freezed/json_serializable/build_runner

## Запуск

```bash
# эмулятор Android (10.0.2.2 = хост, бэкенд из docker compose)
flutter run

# физическое устройство (LAN-IP компьютера с бэкендом)
flutter run --dart-define=API_BASE_URL=http://192.168.x.x:8080
```

### Адрес сервера

Base URL задаётся через `--dart-define=API_BASE_URL=...` (см.
`lib/core/config.dart`) или сохраняется в SQLite (ключ в
`AppConfig.kvBaseUrlKey`) и применяется до первых сетевых вызовов.
Программно сменить адрес в рантайме можно через `ServerSettingsController`
(`serverSettingsProvider.setBaseUrl(...)`) — он переподключает профиль,
синхронизирует состояние и обновляет контент. Дефолт —
`http://10.0.2.2:8080` (эмулятор).

Требования к сети: телефон и компьютер в одной Wi-Fi сети, бэкенд запущен
(`docker compose up -d` в `LDT_2026/`), порт 8080 не блокируется файрволом
(в compose порт опубликован на `0.0.0.0:8080`).

## Новый UI (по «segee»)

- **Создание персонажа** — жёлтые слайды #FFD979: карусель (9 заглушек снежного
  барса), выбор окраса/ушей, имя. Создаёт профиль и питомца через движок.
- **Главный экран** — белая зона под будущего персонажа; свайп нижней панели
  вверх открывает магазин (DraggableScrollableSheet).
- **Магазин** — реальный контент из бандла: спецакция, «Нужное»/«Хотелки»/
  «Награды», цены через `engine.itemPrice` (скидки/перки), запрет минуса.
  Шторка на главной не выше 0.94 экрана, ✕ виден всегда. В лесном походе —
  тот же интерфейс без спецакций, вторая шкала — «Водичка».
- **Дорожка знаний** — Duolingo-стиль: панорама со скруглённой волнистой
  линией пути (цвет линии свой у каждого этапа); переход между этапами —
  ряд из 3 чипов «Этап 1–3» + чип «Бесконечный лес» во всю ширину;
  3 этажа-заглушки (площадка) + бесконечный лес: задание — поход в магазин
  (`ForestTripScreen`): сверху мысль «нужна питательная еда и вода», ребёнок
  сам находит и покупает нужное (без спецакций), после покупок — «В поход!»
  → награда монетами → кулдаун 30 с («зверёк идёт») → следующая точка;
  новый круг — новые цели покупок. Прогресс — в kv (`path_progress_v1`).
- **Задания** — сюжетные (переходы на дорожку) + ежедневные (накормить/
  копилка/покупка, прогресс 1/3); награда — переворачивающаяся карточка:
  4 вида (еда, деньги, ивенты, цели) × 3 качества (обычная/редкая/эпическая,
  веса 60/30/10). Один сбор в день.
- **Цели и заработки** — % заполнения цели (крупные цифры Jersey 10),
  облачко-мысль с эмодзи цели над питомцем; сначала предлагаем выбрать цель,
  пополнение (своя сумма из поля или +10/+20/+50) доступно после выбора;
  выбор цели переносит накопления копилки в прогресс (деньги не теряются).
- **Статусы питомца** — сытость и настроение 0..100 (жёсткий кап при любом
  изменении). Сытость растёт только от еды (покупки с `satiety`, карточка
  «Еда»). Трата: сытость −3 и настроение −2 каждые 5 минут реального
  времени. Настроение: только задания (сюжетные/ежедневные), точки дорожки,
  окончание кулдауна в лесу и первая съеденная еда каждого вида; покупки
  предметов настроение не поднимают. Всплывающие подсказки короткие (1.4 с).
- **Ещё** — финансовый дневник (история из GameState), родительский режим
  (OTP-привязка по link_code, список детей, сводка, бонусы через parent API),
  настройки сервера (адрес, healthz, переподключение).

## Игровой движок (полная игра по спецификации)

Реализованы все 5 периодов по `Context/Infa.md` с контент-бандлом v2
(`backend/migrations/00004_content_v2.sql`, schema 2 — 8 профессий, 27 товаров
(включая продукты: миска с кормом, водичка, молоко, яблоко, рыбка, супчик),
3 цели, 12 заданий, 5 сцен Хитрика, 7 событий, 5 архетипов, 16 терминов):

- **Конечный автомат фаз** (`lib/data/engine/phase_flow.dart`): период 1 —
  диалог → профессия → курс → собеседование → мини-игра → зарплата →
  планирование → магазин → копилка → задания → итоги; периоды 2–5 — пассивный
  доход (если есть источники), тур (период 2), смена профессии (курс+собеседование
  при смене), Хитрик «после зарплаты» и «в магазине», случайные события между
  фазами, резерв с периода 3, откат, анонс следующего периода; период 5 — финал.
- **Экономика** (`lib/data/engine/game_engine.dart`, чистые функции + юнит-тесты):
  зарплаты 8 профессий (+10 за спортзал), СР по таблице правил (кап 50/период,
  переход стадий Малыш/Подросток/Профи только с min_period), архетипы (лидер
  периода, фиксация при 3 периодах доминирования), перки: Мечтатель +10% к
  взносу, Исследователь −5 на товар/период, Ответственный кешбэк 5,
  Творец −10 на аксессуары, Авантюрист +исход турнира; откат времени (сброс
  баланса/покупок/плана/факта; СР/накопления/архетипы/предметы/события
  сохраняются; +10 за неиспользование; «Железная воля» +50 и 👑 без откатов);
  пассивный доход (велосипед/гаджет/огородик/газета); отложенные эффекты
  событий (возврат долга в периоде 3 и т.п.); встроенные задания A1 (план) и
  C2 (сначала нужное) в фазах; лимит родительского бонуса 1..100.
- **Контент**: все 12 форматов заданий (plan_fact_table, slider, story_choice,
  timer_catalog, swipe_cards, find_fake_ad, compare_calculation,
  choice_with_consequences, advice_cards; A1 — в планировании), 16 терминов
  глоссария — в бандле; рендеринг — задача будущего UI.
- **Родительские бонусы**: начисление через parent API при привязке, иначе
  локально; лимит 1..100 (валидация в движке).

## Что работает (инфраструктура)

- Офлайн-игровой цикл целиком на движке: задания, магазин, копилка, цель,
  глоссарий — из встроенного бандла и локальной БД.
- Bootstrap профиля: device_token в secure storage, `POST /v1/profiles`
  идемпотентен; при первом запуске без сети профиль создаётся локально
  (`pending_remote`) и догоняет сервер при появлении сети.
- Синхронизация состояния: PUT с `base_version`, при 409 — мерж
  (серверное состояние как основа, локальные поля с приоритетом) и повтор.
- Контент: старт на встроенном asset → кэш в SQLite → обновление с сервера,
  если версия новее.
- Бонусы родителя: неприменённые бонусы начисляются на баланс с записью в
  историю и подтверждением `POST .../applied`.
- Статус синхронизации доступен через `syncStatusProvider`
  (онлайн/офлайн + текст ошибки для диагностики).
- Запрет отрицательного баланса в магазине — на уровне движка
  (`engine.purchaseItem` возвращает ошибку с объяснением).
